# Anexo A. El artículo de Notion, sección por sección

**Fuente:** «A New Shape for Work», Notion Labs, versión 1.0, 2026. <https://www.notion.com/a-new-shape-for-work>

**Fecha de lectura:** 24 de noviembre de 2026.

El texto no nombra un autor individual. Se describe como una guía de campo para construir un sistema de contexto compartido. Tiene unas diez mil palabras y seis capítulos. Una copia en Markdown vive en Drive.

## Capítulo 1. Introducción

El artículo propone una forma de trabajo en dos partes. La primera parte es un sistema de contexto compartido. La segunda parte son fábricas compartidas. El comienzo más simple es una lista de tareas compartida con un agente.

## Capítulo 2. Qué pasa sin un sistema de contexto

| Sección | Idea |
| --- | --- |
| 2.1 Solo conversar | El texto lista siete síntomas. Ejemplos: los agentes no encuentran la información y cada conversación exige explicar todo de nuevo. |
| 2.2 Fuera de contexto | Una IA sin memoria se parece a una computadora sin disco duro. El contexto compartido funciona como el sistema nervioso de la organización. |
| 2.3 Fuera de guion | Un agente es un programa que ejecuta instrucciones en lenguaje natural. Esas instrucciones se llaman *skills*. |
| 2.4 «En mi máquina funciona» | Una skill compartida falla porque cada persona tiene un agente, un modelo y unas herramientas distintas. |
| 2.5 De conversaciones a sistemas | El trabajo debe empezar con disparadores automáticos, programados o por evento. |
| 2.6 El «impuesto de configuración» | Una fábrica evita que cada persona configure su propio agente. |
| 2.7 No atarse a un proveedor | El mejor modelo y el mejor espacio de trabajo son decisiones separadas. La frase central es «Rent the intelligence. Own the context.» |
| 2.8 Una frontera irregular | La competencia de los modelos es desigual: son fuertes en código y débiles en redacción y diseño. |

## Capítulo 3. El sistema de contexto

| Sección | Idea |
| --- | --- |
| 3.1 Qué es | El sistema cumple seis tareas: guardar, organizar, gobernar, mostrar, colaborar y funcionar con cualquier agente. |
| 3.2 Por qué no construirlo en casa | Una plataforma resuelve la seguridad, la integración con agentes, los permisos y la colaboración. |
| 3.3 Almacenamiento estructurado | Los datos estructurados deben seguir estructurados. Los documentos deben poder encontrarse. |
| 3.4 Ontología | Conviene tener pocas bases de datos centrales: proyectos, tareas, documentos, personas, equipos y clientes. |
| 3.5 Estructura fractal | La misma estructura se repite en cada nivel. «A little structure goes a long way.» |
| 3.6 Sincronización | Conviene traer todas las fuentes a un solo sistema, como un almacén de contexto. |
| 3.7 Reuniones | Las transcripciones son una fuente rica de contexto. |
| 3.8 Permisos | Los permisos por grupo, por fila y por columna reemplazan al documento privado por defecto. |
| 3.9 Edición y colaboración | Las personas también necesitan una buena interfaz. |
| 3.10 Validación | El sistema debe rechazar la entrada defectuosa, como un formulario. |
| 3.11 Contexto podrido | El contexto desactualizado es el enemigo principal. Los agentes abaratan el mantenimiento. |

## Capítulo 4. Las fábricas

| Sección | Idea |
| --- | --- |
| 4.1 Qué es una fábrica | Es un sistema de IA compartido para una tarea específica. Tiene tres atributos: específica, compartida y vigilada. |
| 4.2 Por qué importan | Los agentes personales duplican el costo fijo y mejoran poco. Un equipo central observa muchas más corridas. |
| 4.3 Las skills | Una skill es una «protofábrica»: nadie la vigila y no se comparte de verdad. |
| 4.4 Qué no es | No es una fábrica sin supervisión humana. Las personas participan donde importa. |
| 4.5 Economías de escala | El costo fijo de una fábrica de IA es bajo, según el artículo. Por eso conviene centralizar. |
| 4.6 La fábrica más simple | Tiene seis pasos: una base de datos, una columna de estado, un agente, el flujo de estados, el acceso compartido y la mejora del prompt. |

## Capítulo 5. Cuatro pasos para construir una fábrica

| Paso | Idea |
| --- | --- |
| 5.1 Observar | Un buen candidato es recurrente, verificable, estable, digital y de calidad estándar. Además, su universo de información es conocido y sus errores cuestan poco. |
| 5.2 Planear | Hay que definir los insumos, las etapas, los resultados y las herramientas. Conviene empezar simple. |
| 5.3 Correr | Primero se hacen corridas en sombra, que producen borradores y no envíos. El volumen se controla. |
| 5.4 Mejorar | Los prompts se versionan con un estado: en prueba, en producción o retirado. Las evaluaciones tienen tareas y criterios escritos. |

## Capítulo 6. Conclusión

Las personas quieren ser útiles y dominar un oficio. El artículo afirma que la IA no cambia ese deseo.

## Evaluación

**Argumentos con ejemplo.** El artículo explica bien las fallas de los agentes personales. También explica los requisitos de un sistema de contexto y el uso de corridas en sombra.

**Afirmaciones sin respaldo.** Las cifras «mil veces», «diez o cien veces» y «cinco minutos» no tienen fuente. La afirmación «las fábricas son inevitables» descansa en costos que el texto no documenta.

**Tensiones internas.** El texto dice que todo el trabajo no creativo se automatizará. Después dice que el objetivo no es retirar a las personas. El texto critica las plataformas verticales y recomienda la suya.
